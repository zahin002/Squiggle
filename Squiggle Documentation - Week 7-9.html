1. Phase Overview

The goal of Week 7–9 was to transition the project from a "lobby and free-draw sandbox" into a fully functional, timed, round-based game. We implemented complex timers, game state logic, word selections, and fully automated Skribbl-style hint reveal mechanics.

Main Objective: Seamlessly orchestrate the round lifecycle (Lobby -> Word Selection -> Drawing/Guessing -> End Round) using Socket.IO, while squashing critical state-management bugs.

2. Features Implemented

  • ✅ 25-Second Word Selection Phase: The drawer is given 3 word choices and has 25 seconds to pick one. If they fail to pick, the server automatically selects one for them.
  • ✅ Canvas Freezing Guard: The drawing canvas is completely locked out for the drawer until they actually select a word and the drawing phase begins.
  • ✅ Dynamic Skribbl Auto-Hints: Guesses get automated hints based strictly on mathematical logic depending on word length.
  • ✅ Automated Ghost Room Sweeper: A cron-job runs every 60 seconds to scan for dead rooms and completely wipes them from memory and MongoDB.
  • ✅ Spectator Safeguards: Spectators do not keep rooms alive. If all active players leave, the room instantly collapses and spectators are kicked to the lobby.

3. Step-by-Step Code Walkthrough (For Beginners)

This section breaks down the most essential blocks of code we wrote this week so that anyone with zero basics can understand exactly how our backend and frontend talk to each other.

A. The Canvas Freeze Logic (Frontend)

This code lives inside client/src/components/DrawingCanvas.jsx. We needed a way to physically prevent the drawer from drawing while they were supposed to be picking a word.

const handleMouseDown = useCallback((e) => {
  // If the game phase is not 'playing', STOP the function immediately
  if (status !== 'playing') return;

  // Otherwise, if you are the drawer, start drawing!
  if (isDrawer) {
    startDrawing(e);
  }
}, [isDrawer, startDrawing, status]);
What this means: When the user clicks their mouse on the canvas, this function runs. The very first line checks the status variable. If the status is 'wordSelection' or 'lobby', the return; command forces the function to exit immediately before doing anything else.

How it connects: The status variable is passed down from GamePage.jsx, which gets its value directly from the Socket.IO server. Because we added status to the dependency array [isDrawer, startDrawing, status], React will always use the freshest, most up-to-date status!

B. The Zombie Room Sweeper (Backend)

This code lives at the bottom of server/socket/gameEvents.js. Its job is to hunt down dead rooms and delete them from the database.

// Run this block of code every 60,000 milliseconds (1 minute)
setInterval(async () => {
  const now = Date.now();
  
  // Loop through every single room in our active memory
  for (const [roomId, room] of rooms.entries()) {
    
    // Calculate how many milliseconds since the room was last active
    const inactiveTime = now - (room.lastActive || now);
    
    // If it has been more than 15 minutes (900,000 ms)...
    if (inactiveTime > 15 * 60 * 1000) {
      
      // Delete the room from server memory
      deleteRoom(roomId);
      
      // Tell MongoDB to delete the room so it vanishes from the Lobby
      await require('../models/Room').deleteOne({ roomId });
    }
  }
}, 60000);
What this means: We created an infinite loop (setInterval) that acts like a janitor. It checks the lastActive timestamp of every room. If a room has been sitting empty and quiet for 15 minutes, it completely destroys it.

How it connects: By calling Room.deleteOne, it directly talks to our MongoDB database. This ensures that the "Public Rooms" list on the frontend Lobby page stays perfectly clean and doesn't get clogged up with empty, abandoned rooms.

C. The Auto-Hint Distribution Algorithm (Backend)

This code calculates exactly how many hints to give a word, and randomly drops them over time. It lives in the round manager.

// 1. Calculate max hints based on how long the word is
let maxHints = 0;
if (len === 4) maxHints = 1;
else if (len >= 5 && len <= 7) maxHints = Math.floor(Math.random() * 3) + 2; // Gives 2, 3, or 4 hints
else if (len >= 8 && len <= 9) maxHints = Math.floor(Math.random() * 2) + 4; // Gives 4 or 5 hints

// 2. Decide if we should drop a hint RIGHT NOW
const timePercentage = room.timeLeft / room.settings.drawTime; 
let expectedHints = Math.floor((1 - timePercentage) * (maxHints + 1));

// If we haven't revealed enough hints yet, reveal one!
if (expectedHints > room.hintsRevealed.length) {
    revealRandomHint();
}
What this means: First, we use basic if/else statements to say "if the word is 5 letters long, give it 2 to 4 hints max".
Second, we look at the clock. If the round is 50% finished (timePercentage = 0.5), the system expects 50% of the hints to be revealed. If it notices it is behind schedule, it drops a new hint.

How it connects: Every single second, the main round countdown timer runs this exact block of code. If a hint is revealed, it emits a hintRevealed Socket.IO event to all guessers, and the blank spaces _ _ _ on their screen magically fill in with a letter!

4. Debugging & Issues Faced

Issue #1: The Canvas Freeze Bug

The Problem: We locked the canvas during the "Word Selection" phase. However, when the drawer finally selected a word and the phase shifted to "playing", the canvas remained frozen for several seconds, reducing their draw time.

The Investigation: Initially, we suspected network lag. However, tracing the Socket events proved the backend was instantly telling the frontend the status was 'playing'. The issue was actually a Stale React Closure.

The Fix: Inside DrawingCanvas.jsx, the handleMouseMove and handleMouseUp functions were wrapped in useCallback hooks. We forgot to add the new status variable to the dependency array (as shown in the code walkthrough above). React was executing the mouse events using the old memory reference of the status (which was still 'wordSelection'). Adding status to the dependency array fixed it instantly.

Issue #2: The MongoDB "Zombie Rooms" Bug

The Problem: When players created rooms and later the server crashed or restarted, the rooms would permanently remain on the "Public Rooms" list in the lobby, but clicking them would cause an error.

The Investigation: Active rooms are tracked in an in-memory Map, but they are also saved to MongoDB so the lobby can read them via an API. When the Node server restarts, the RAM (in-memory Map) is wiped clean, but MongoDB persists. Because the memory was wiped, our cleanup scripts didn't know those rooms existed to delete them!

The Fix: First, we updated the standard deleteRoom function to ensure it always executes Room.deleteOne(). Second, we injected a script into server/index.js during the database connection phase. Now, every time the backend boots up, it automatically runs Room.deleteMany({}), ensuring the server always starts with a perfectly clean database, entirely eliminating ghost rooms.

🎓 Final Viva Preparation

1. How did you handle the synchronization between the timer on the server and the clients?

The timer is strictly managed on the backend inside roundManager.js using a setInterval. Every second, it decreases room.timeLeft and emits a timerTick event to all clients in the room via Socket.IO. We never trust the client's clock because clients could manipulate their local time or experience browser lag.

2. How does the hint system work dynamically? Why not just hardcode the hint drops?

Because words range from 3 letters to 15+ letters, hardcoding when a hint reveals doesn't scale. Our backend randomly allocates a maximum number of hints based on a math formula. Then, it uses the formula Math.floor((1 - timePercentage) * (maxHints + 1)) to mathematically distribute exactly that amount of hints evenly across whatever time remains in the round.

3. What happens if the drawer never picks a word? Does the game freeze?

No. We implemented a wordSelectionTimer. When the word choices are sent to the drawer, the backend starts a 25-second countdown. If the drawer fails to emit a wordSelected event before it hits 0, the backend intercepts the process, randomly selects one of the 3 choices on their behalf, and forces the round to start.

4. How did you fix the React "Stale Closure" bug in the drawing canvas?

React's useCallback caches functions to prevent unnecessary re-renders. If a variable used inside that function changes, but isn't listed in the dependency array, the function will forever use the old value. We fixed the canvas freeze bug by adding our status variable to the useCallback dependency arrays for mouse events.
