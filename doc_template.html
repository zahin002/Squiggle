1. Project Overview

Squiggle is a real-time multiplayer drawing and guessing game inspired by popular social drawing games such as Skribbl.io.


The goal of Week 3–4 was to create the complete foundation required before actual gameplay begins.

Main Objective: Create a secure authentication system and multiplayer room management system that allows users and guests to gather in game rooms before starting matches.

Features Implemented During Week 3–4

  • ✅ Room Creation

  • ✅ Public Room Browser
  • ✅ Socket.IO Synchronization
  • ✅ Live Player List Updates
  • ✅ Player Leave Detection

8. Password Security (bcrypt)

Passwords should NEVER be stored as plain text.

Wrong Way


{
  username: "test123",
  password: "123456"
}

Anyone with database access could immediately see the password.

Correct Way


{
  username: "test123",
  password:
  "$2b$12$yV6x3dM..."
}

bcrypt converts the password into an irreversible hash.

Password Hashing Code


userSchema.pre('save', async function () {

    if (!this.isModified('password'))
        return;

    this.password =
        await bcrypt.hash(this.password, 12);

});

What Happens?

  1. User enters password
  2. bcrypt hashes password
  3. Hash stored in database
  4. Original password discarded
Even project developers cannot recover a user's original password.

12. JWT Authentication

JWT stands for JSON Web Token. It allows the server to verify user identity without storing sessions.

Why JWT?

  • Stateless authentication
  • Scalable
  • Fast verification
  • Industry standard

JWT Structure


HEADER
.
PAYLOAD
.
SIGNATURE

Example Token


eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

JWT Generation


const token = jwt.sign(

{
   id:user._id,
   username:user.username
},

process.env.JWT_SECRET,

{
   expiresIn:'7d'
}

);

Information Stored in Token

Field Purpose
id User identifier
username Player name
The token is stored in browser localStorage and attached to future requests.

🎓 Viva Questions (Authentication)

Q: Why use bcrypt?

bcrypt prevents passwords from being stored in plain text and protects users if the database is compromised.

Q: Why hash passwords?

Because plain text passwords are a major security risk.

Q: Why use JWT instead of sessions?

JWT is stateless and scales better for distributed applications.

Q: What happens when a user logs in?

The password is verified, a JWT token is generated and returned to the client.

Q: Where is the token stored?

Inside browser localStorage.

Q: What information is stored inside JWT?

User ID and username.

37. Password Hashing Bug

One of the most difficult bugs occurred during registration testing.

Symptoms

  • Registration API froze
  • Postman never returned a response
  • User creation stopped at save()

Investigation

Debug logs were added: 

console.log("BODY");
console.log("EXISTS");
console.log("USER CREATED");
console.log("USER SAVED");
The logs revealed execution stopped before: 

USER SAVED

Root Cause

Problem originated inside: 

userSchema.pre('save')
Incorrect middleware behavior caused Mongoose save() to never finish.

Final Fix


userSchema.pre('save', async function () {

   if(!this.isModified('password'))
      return;

   this.password =
      await bcrypt.hash(this.password,12);

});

Lesson Learned

Always isolate database hooks when save() operations freeze.
